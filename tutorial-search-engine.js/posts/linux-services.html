Linux Services & Log Management

Systemctl Commands

Managing services with systemd:

# Check service status
sudo systemctl status nginx

# Start/stop/restart service
sudo systemctl start nginx
sudo systemctl stop nginx
sudo systemctl restart nginx

# Enable/disable service at boot
sudo systemctl enable nginx
sudo systemctl disable nginx

# Reload service configuration
sudo systemctl reload nginx

# List all services
systemctl list-units --type=service

# List failed services
systemctl --failed

Analyzing Boot Performance

Use systemd-analyze to inspect boot-up performance:

# Time taken to boot
systemd-analyze

# Time each service took to start
systemd-analyze blame

# Critical chain of services
systemd-analyze critical-chain

# Generate an SVG plot of the boot process
systemd-analyze plot > boot.svg

Journald (System Logs)

View and manage system logs with journalctl:

# View all logs
sudo journalctl

# Follow logs in real-time
sudo journalctl -f

# Logs for specific service
sudo journalctl -u nginx

# Logs since boot
sudo journalctl -b

# Logs from last hour
sudo journalctl --since "1 hour ago"

# Logs with priority (err, warning, etc.)
sudo journalctl -p err

# Output in JSON format
sudo journalctl -o json-pretty

# Filter by executable
sudo journalctl /usr/sbin/nginx

# Clear old logs
sudo journalctl --vacuum-time=7d
sudo journalctl --vacuum-size=500M

Log Rotation (logrotate)

logrotate is used to manage log files, including rotation, compression, and removal. Configurations are typically in /etc/logrotate.conf and /etc/logrotate.d/.

# Example config in /etc/logrotate.d/myapp
/var/log/myapp/*.log {
  daily
  missingok
  rotate 14
  compress
  delaycompress
  notifempty
  create 640 myapp myapp
  sharedscripts
  postrotate
    systemctl reload myapp > /dev/null 2>&1 || true
  endscript
}

# Force a log rotation
sudo logrotate -f /etc/logrotate.conf

User Services

You can run services as a regular user using systemctl --user. Service files are placed in ~/.config/systemd/user/.

# Enable and start a user service
systemctl --user enable myapp
systemctl --user start myapp

# To have user services start on boot, you may need to enable lingering for that user
sudo loginctl enable-linger username

Creating a Custom Service

Create a systemd service file at /etc/systemd/system/myapp.service:

[Unit]
Description=My Application
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/myapp
ExecStart=/usr/bin/python3 /opt/myapp/app.py
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target

Then enable and start:

sudo systemctl daemon-reload
sudo systemctl enable myapp
sudo systemctl start myapp

Process Management

# Find process by name
ps aux | grep nginx
pgrep nginx

# Kill process
kill PID
kill -9 PID  # Force kill
pkill nginx  # Kill by name

# Check port usage
sudo netstat -tulpn | grep :80
sudo ss -tulpn | grep :80
sudo lsof -i :80

Log File Locations

  • /var/log/syslog - System logs (Debian/Ubuntu)
  • /var/log/messages - System logs (RHEL/CentOS)
  • /var/log/auth.log - Authentication logs
  • /var/log/nginx/ - Nginx logs
  • /var/log/apache2/ - Apache logs

Quick Troubleshooting

# Check disk space
df -h

# Check memory usage
free -h

# Check system load
uptime
top
htop

# Check service dependencies
systemctl list-dependencies nginx

Practice Checklist

  • Check service status before restarting anything.
  • Read recent logs when a service fails.
  • Confirm configuration syntax before reloads.
  • Change one setting at a time.
  • Document the expected recovery path.
