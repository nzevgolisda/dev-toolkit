WSL Performance Optimization

File System Performance

Store Projects in WSL

# Bad: Accessing Windows files from WSL is slow
cd /mnt/c/Users/Name/Projects

# Good: Store in WSL filesystem
cd ~/projects

# Benchmark the difference
time ls -lR /mnt/c/Users/Name/LargeProject  # Slow
time ls -lR ~/LargeProject                  # Fast

Exclude WSL Folders from Windows Defender

In PowerShell as Administrator:

# Get WSL installation path
$wslPath = "$env:LOCALAPPDATA\Packages"

# Exclude WSL distro folders
Add-MpPreference -ExclusionPath "$wslPath\CanonicalGroupLimited.Ubuntu*"
Add-MpPreference -ExclusionPath "$env:USERPROFILE\AppData\Local\Docker\wsl"

Memory Configuration

Create/edit %USERPROFILE%\.wslconfig:

[wsl2]
# Limit memory to 8GB
memory=8GB

# Limit processors
processors=4

# Set swap size
swap=2GB

# Disable page reporting (can improve performance)
pageReporting=false

# Set swap file location
swapFile=C:\\temp\\wsl-swap.vhdx

Disk I/O Optimization

Use VHD on SSD

# Move WSL distro to faster drive
# Export distro
wsl --export Ubuntu-22.04 D:\WSL\ubuntu-backup.tar

# Unregister
wsl --unregister Ubuntu-22.04

# Import to new location
wsl --import Ubuntu-22.04 D:\WSL\Ubuntu D:\WSL\ubuntu-backup.tar

Sparse VHD

# Reclaim disk space (from PowerShell as Admin)
wsl --shutdown

# Optimize VHD
Optimize-VHD -Path "$env:LOCALAPPDATA\Packages\CanonicalGroupLimited.Ubuntu*\LocalState\ext4.vhdx" -Mode Full

WSL Configuration

Edit /etc/wsl.conf:

[boot]
systemd=true

[automount]
enabled = true
options = "metadata,umask=22,fmask=11"
mountFsTab = true

[network]
generateHosts = true
generateResolvConf = true

[interop]
enabled = true
appendWindowsPath = false  # Faster PATH lookup

Shell Performance

Optimize PATH

# In .bashrc, remove Windows paths if not needed
export PATH="/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin"

# Or selectively add Windows tools
export PATH="/usr/local/bin:/usr/bin:/bin:$PATH"
export PATH="$PATH:/mnt/c/Windows/System32"

Disable Windows PATH Appending

# In /etc/wsl.conf
[interop]
appendWindowsPath = false

# Then manually add needed Windows tools
export PATH="$PATH:/mnt/c/Windows/System32:/mnt/c/Windows"

Git Performance

# Use WSL git, not Windows git
which git  # Should show /usr/bin/git

# Enable git file system monitor
git config --global core.fsmonitor true
git config --global core.untrackedcache true

# Increase buffer for large repos
git config --global http.postBuffer 524288000

Node.js Performance

# Install Node.js in WSL, not Windows
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

# Use pnpm for faster package installation
npm install -g pnpm

# Or use Yarn
npm install -g yarn

# Enable caching
npm config set cache ~/.npm-cache --global

Docker Performance

# Use Docker Desktop with WSL2 backend

# In .wslconfig, allocate enough resources
[wsl2]
memory=8GB
processors=4

# Use BuildKit for faster builds
export DOCKER_BUILDKIT=1

# Clean up regularly
docker system prune -a

Build Performance

# Use all CPU cores for compilation
export MAKEFLAGS="-j$(nproc)"

# For npm builds
npm config set jobs max

# For Python builds
pip install --upgrade pip setuptools wheel

Monitoring Performance

# Check WSL resource usage from Windows
wsl -l -v

# Inside WSL, monitor resources
htop
free -h
df -h

# Check disk I/O
iostat -x 1

# Monitor network
iftop

Startup Optimization

Clean .bashrc

# Profile .bashrc startup time
time bash -i -c exit

# Use lazy loading for tools
# Instead of: eval "$(rbenv init -)"
# Use:
rbenv() {
  unset -f rbenv
  eval "$(command rbenv init -)"
  rbenv "$@"
}

Reduce systemd Services

# List services
systemctl list-units --type=service

# Disable unnecessary services
sudo systemctl disable service-name
sudo systemctl stop service-name

Network Performance

# In .wslconfig, try experimental network mode
[wsl2]
networkingMode=mirrored
dnsTunneling=true
firewall=true

# Requires Windows 11 22H2 or later
# Restart WSL: wsl --shutdown

Benchmarking

# CPU benchmark
sysbench cpu --threads=$(nproc) run

# Memory benchmark
sysbench memory --threads=$(nproc) run

# File I/O benchmark
dd if=/dev/zero of=testfile bs=1M count=1024 oflag=direct
rm testfile

# Compare WSL vs Windows filesystem
time find ~/project -name "*.js" | wc -l
time find /mnt/c/project -name "*.js" | wc -l

Quick Wins Checklist

  • ✓ Store code in WSL filesystem, not /mnt/c/
  • ✓ Exclude WSL from Windows Defender
  • ✓ Allocate enough RAM in .wslconfig
  • ✓ Use WSL versions of tools (git, node, python)
  • ✓ Disable appendWindowsPath if not needed
  • ✓ Keep WSL updated: wsl --update
  • ✓ Restart WSL after config changes: wsl --shutdown
  • ✓ Use SSD for WSL installation

Advanced: Custom Kernel

For advanced users, compiling your own Linux kernel for WSL can yield performance benefits. This allows you to enable specific features, optimize for your hardware, and remove unused drivers.

# 1. Clone the WSL2-Linux-Kernel repository from Microsoft's GitHub
git clone https://github.com/microsoft/WSL2-Linux-Kernel.git
cd WSL2-Linux-Kernel

# 2. Copy your existing config or start fresh
cp /proc/config.gz .
gunzip config.gz
mv config .config

# 3. Customize the kernel config
make menuconfig

# 4. Compile the kernel
make -j$(nproc)

# 5. In %USERPROFILE%/.wslconfig, point to your new kernel
[wsl2]
kernel=C:\\path\\to\\your\\WSL2-Linux-Kernel\\arch\\x86\\boot\\bzImage

Practice Checklist

  • Measure before changing filesystem or memory settings.
  • Keep active Linux projects together when possible.
  • Stop unused distributions to reclaim resources.
  • Compare cold and warm command timings.
  • Record changes so they can be reversed.
