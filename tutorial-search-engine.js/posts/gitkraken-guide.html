GitKraken Guide

A visual workflow for reviewing, branching, and resolving Git changes.

Start With a Repository

  1. Open GitKraken and choose Open a repo or Clone a repo.
  2. Confirm the working directory and remote in the repository panel.
  3. Fetch before starting work so the graph reflects the latest remote state.
  4. Select the branch you want to work from and create a descriptive feature branch.

Review Changes

The left panel shows changed files, while the diff view lets you inspect additions and deletions before staging.

  • Click a file to review its diff.
  • Stage only the hunks that belong to the current change.
  • Write a short commit summary that describes the result.
  • Use the commit graph to verify the branch and parent commit.

Branches and Pull Requests

# A matching CLI workflow
git fetch origin
git switch -c feature/search-tutorials
git add TutorialSite/
git commit -m "Add searchable tutorial library"
git push -u origin feature/search-tutorials

GitKraken presents the same operations visually. Keep feature branches small, pull or fetch before publishing, and open a pull request from the branch rather than committing directly to the default branch.

Resolve Conflicts

  1. Pull or merge the target branch and open the conflict view.
  2. Review each side and choose the intended result, not simply “ours” or “theirs”.
  3. Save the resolved file and mark it resolved.
  4. Run tests, then commit the merge or continue the rebase.

Good Habits

  • Use names that explain branch purpose.
  • Review staged files before every commit.
  • Keep generated files and secrets out of commits.
  • Use the graph to explain history during code review.

Practice Checklist

  • Review the graph before starting a merge.
  • Stage only files belonging to the current task.
  • Use descriptive branch names and commit messages.
  • Resolve conflicts by understanding both changes.
  • Run checks before pushing a branch.
