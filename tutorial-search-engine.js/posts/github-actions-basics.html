GitHub Actions Basics

Automate checks with small, repeatable workflow files.

A First Workflow

name: Test

on:
  push:
    branches: [main]
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
      - run: npm ci
      - run: npm test

Save this as .github/workflows/test.yml. A workflow responds to events, creates jobs on runners, and executes ordered steps.

Triggers and Jobs

  • Use pull_request for checks before merging.
  • Use push for branch and release automation.
  • Give each job one clear responsibility.
  • Use a matrix when the same checks need multiple runtimes.
strategy:
  matrix:
    node: [20, 22]
steps:
  - uses: actions/setup-node@v4
    with:
      node-version: ${{ matrix.node }}

Secrets and Permissions

Never put tokens directly in workflow files. Store sensitive values in repository or environment secrets and reference them through the secrets context.

permissions:
  contents: read

steps:
  - run: ./deploy.sh
    env:
      DEPLOY_TOKEN: ${{ secrets.DEPLOY_TOKEN }}

Reliable Workflows

  • Pin action major versions and review updates.
  • Cache dependencies only after the uncached job works.
  • Use artifacts for test reports and build output.
  • Keep deployment jobs behind an environment approval.

Practice Checklist

  • Run checks on pull requests before merging.
  • Keep permissions as narrow as possible.
  • Review logs and artifacts after failures.
  • Never print secrets in workflow output.
  • Keep deployment steps separately reviewable.
