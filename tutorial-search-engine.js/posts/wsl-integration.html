WSL Windows Integration

File System Access

Access Windows Files from WSL

# Windows drives are mounted under /mnt
cd /mnt/c/Users/YourUsername/Documents
cd /mnt/d/Projects

# Navigate to Windows home
cd /mnt/c/Users/$USER

# Create symbolic link for easier access
ln -s /mnt/c/Users/YourUsername ~/winuser

Access WSL Files from Windows

# In File Explorer, type:
\\wsl$\Ubuntu-22.04\home\username

# Or from command prompt:
\\wsl$\Ubuntu-22.04\

# Open Windows Explorer from WSL
explorer.exe .
explorer.exe /mnt/c/Users

Running Windows Commands from WSL

# Run any Windows executable
notepad.exe file.txt
code.exe .
powershell.exe -Command "Get-Process"

# Use cmd.exe
cmd.exe /c dir

# Pipe between WSL and Windows
ls -la | clip.exe  # Copy to Windows clipboard
echo "test" | clip.exe

Running Linux Commands from Windows

# From PowerShell or CMD
wsl ls -la
wsl grep "pattern" file.txt
wsl python3 script.py

# Run command in specific distro
wsl -d Ubuntu-22.04 python3 --version

# Run as specific user
wsl -u root apt update

Environment Variables

Access Windows Environment Variables

# View Windows PATH from WSL
echo $PATH | grep -o "/mnt/c[^:]*"

# Access Windows environment variables
wslpath -u "$(cmd.exe /c echo %USERPROFILE%)"

# Convert paths
wslpath -w ~/projects  # Convert to Windows path
wslpath -u 'C:\Users'  # Convert to WSL path

Share Environment Variables

# In /etc/wsl.conf
[interop]
enabled = true
appendWindowsPath = true

# To enable systemd support (for services like Docker, microk8s)
[boot]
systemd=true

Access Windows env vars

printenv | grep USERPROFILE

Git Credential Sharing

# Use Windows Git Credential Manager
git config --global credential.helper \
  "/mnt/c/Program\\ Files/Git/mingw64/bin/git-credential-manager.exe"

# Or use Windows credential store
git config --global credential.helper manager-core

SSH Key Sharing

# Copy Windows SSH keys to WSL
cp -r /mnt/c/Users/YourUsername/.ssh ~/
chmod 700 ~/.ssh
chmod 600 ~/.ssh/id_rsa
chmod 644 ~/.ssh/id_rsa.pub

# Or create symbolic link
ln -s /mnt/c/Users/YourUsername/.ssh ~/.ssh
chmod 700 ~/.ssh
chmod 600 ~/.ssh/*

Running GUI Apps with WSLg

WSLg (Windows Subsystem for Linux GUI) is built-in to modern versions of WSL and allows you to run Linux GUI applications seamlessly.

# First, update your WSL instance
wsl --update

# Install a GUI application
sudo apt update
sudo apt install gedit -y

# Run the application from your WSL terminal
gedit

# The application window will appear on your Windows desktop.
# You can also find it in your Start Menu under the distribution's folder (e.g., "Ubuntu").

Useful Scripts

Convert Path Function

# Add to .bashrc
winpath() {
  wslpath -w "$1"
}

linuxpath() {
  wslpath -u "$1"
}

# Usage
winpath ~/projects
linuxpath 'C:\Users\Name\Documents'

Quick Open in Explorer

# Add to .bashrc
explore() {
  explorer.exe "${1:-.}"
}

# Usage
explore           # Open current directory
explore ~/projects # Open specific directory

Configuration Best Practices

  • Store code in WSL filesystem (~/) for better performance
  • Use Windows tools (VS Code, browsers) with WSL backend
  • Share credentials between Windows and WSL
  • Use symbolic links for frequently accessed Windows directories
  • Configure proper file permissions in /etc/wsl.conf
  • Use Windows Terminal for the best terminal experience

Troubleshooting Common Issues

  • "Command not found" for Windows executables: Ensure `appendWindowsPath` is `true` in `/etc/wsl.conf`.
  • Slow performance: Make sure your project files are in the WSL filesystem (e.g., `~/projects`), not the Windows filesystem (`/mnt/c/...`).
  • Network issues: If you can't access services, try `wsl --shutdown` and restart your terminal. Also check Windows Firewall rules.
  • GUI apps not working: Run `wsl --update` to ensure you have the latest version of WSL and WSLg.
  • File permission errors: Use the `metadata` option in `/etc/wsl.conf` to get more granular control over file permissions on mounted Windows drives.

Practice Checklist

  • Choose one canonical location for each project.
  • Use explicit path conversion at boundaries.
  • Check newline and permission behavior in scripts.
  • Keep credentials out of shared mounts.
  • Test commands from both environments.
