Git Workflows & Best Practices

Basic Workflow

# Clone repository
git clone https://github.com/user/repo.git
cd repo

# Create feature branch
git checkout -b feature/new-feature

# Make changes and commit
git add .
git commit -m "Add new feature"

# Push to remote
git push origin feature/new-feature

Branch Management

# List all branches
git branch -a

# Switch to branch
git checkout main

# Create and switch to new branch
git checkout -b feature/branch-name

# Delete local branch
git branch -d branch-name

# Delete remote branch
git push origin --delete branch-name

# Rename current branch
git branch -m new-name

Committing Changes

# Stage specific files
git add file1.txt file2.txt

# Stage all changes
git add .

# Stage with interactive mode
git add -p

# Commit with message
git commit -m "Descriptive commit message"

# Amend last commit
git commit --amend -m "Updated message"

# Amend without changing message
git commit --amend --no-edit

Syncing with Remote

# Fetch changes from remote
git fetch origin

# Pull changes (fetch + merge)
git pull origin main

# Pull with rebase
git pull --rebase origin main

# Push changes
git push origin branch-name

# Force push (use carefully!)
git push --force-with-lease origin branch-name

Undoing Changes

# Discard unstaged changes
git checkout -- filename

# Unstage files
git reset HEAD filename

# Undo last commit (keep changes)
git reset --soft HEAD~1

# Undo last commit (discard changes)
git reset --hard HEAD~1

# Revert a commit (creates new commit)
git revert commit-hash

Finding Bugs with Bisect

# Start a bisect session
git bisect start

# Mark the current commit as bad
git bisect bad

# Mark a known good commit
git bisect good 

# Git will checkout a commit in the middle.
# Test the code, then run 'git bisect good' or 'git bisect bad'
# Repeat until Git identifies the bad commit.

# End the bisect session
git bisect reset

Cherry Picking Commits

# Apply a commit from another branch
git cherry-pick 

# Cherry-pick a range of commits
git cherry-pick ^..

# If there are conflicts, resolve them and continue
git cherry-pick --continue

Stashing

# Stash current changes
git stash

# Stash with message
git stash save "Work in progress on feature X"

# List stashes
git stash list

# Apply most recent stash
git stash apply

# Apply and remove stash
git stash pop

# Apply specific stash
git stash apply stash@{2}

# Delete stash
git stash drop stash@{0}

Merging & Rebasing

# Merge branch into current
git merge feature-branch

# Abort merge
git merge --abort

# Rebase current branch
git rebase main

# Interactive rebase (last 3 commits)
git rebase -i HEAD~3

# Continue rebase after resolving conflicts
git rebase --continue

# Abort rebase
git rebase --abort

# --- Interactive Rebase Commands ---
# p, pick = use commit
# r, reword = use commit, but edit the commit message
# e, edit = use commit, but stop for amending
# s, squash = use commit, but meld into previous commit
# f, fixup = like "squash", but discard this commit's log message
# d, drop = remove commit

Viewing History

# View commit history
git log

# Compact one-line view
git log --oneline

# Graph view
git log --oneline --graph --all

# Show changes in each commit
git log -p

# Show commits by author
git log --author="Name"

# Show commits in date range
git log --since="2 weeks ago"

Useful Aliases

Add to your ~/.gitconfig:

[alias]
    st = status
    co = checkout
    br = branch
    ci = commit
    unstage = reset HEAD --
    last = log -1 HEAD
    visual = log --oneline --graph --all --decorate
    amend = commit --amend --no-edit

Best Practices

  • Write clear, descriptive commit messages
  • Commit early and often with logical changes
  • Always pull before pushing
  • Use branches for features and bug fixes
  • Review changes before committing
  • Never force push to shared branches
  • Keep commits atomic and focused

Workflow Models

  • GitFlow: A robust framework using feature branches, develop, release, hotfix, and main branches. Good for projects with scheduled releases. Learn more.
  • GitHub Flow: A simpler model where `main` is always deployable. Feature branches are created from `main` and merged back after review. Ideal for CI/CD. Learn more.
  • Trunk-Based Development: All developers commit to a single branch (`trunk` or `main`). Feature flags are used to hide incomplete features. Good for experienced teams and rapid iteration. Learn more.

Practice Checklist

  • Inspect status and the diff before staging.
  • Keep each commit focused and easy to review.
  • Fetch before comparing work with the remote.
  • Use a branch for changes that are not ready.
  • Write down the recovery command before risky operations.
